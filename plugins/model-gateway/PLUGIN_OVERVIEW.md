Keep coding when a Claude or ChatGPT account reaches its limit. Supported BB
harnesses keep working across provider limits without moving a conversation to
another thread.

## What you get

Model Gateway gives Claude Code, Codex, omp, FX, nanocodex, Prime Agent, and Pi an ordered
chain of provider accounts and API-key fallbacks. A thread stays on its selected
upstream during a tool loop, then can return to the primary account on a later
turn after its limit resets.

The Settings page shows accounts, routes, model mappings, holds, and active
fallbacks. The Sandboxes plugin's machine icon in the thread header shows the
upstream and model serving the current conversation. The same controls are available through `bb gateway` commands.

## Protocol translation

The gateway translates between Anthropic Messages and OpenAI Responses when a
fallback speaks a different protocol. Replay guards prevent reasoning or
thinking data created by one upstream from being sent to another upstream.

## Optional integrations

Claude Code and Codex work without another plugin or agent adapter. omp and Pi
use setup files generated by `bb gateway setup host`. Hempi and agent profiles
share Pi's chain and routing. FX, nanocodex, and Prime Agent use separate,
optional ACP adapters; Model Gateway neither installs nor requires them.
Routed FX and Prime Agent need no local provider login.

Automatic model selection through Jev is optional. It sends the truncated last
user message and candidate model names to OpenRouter for each eligible turn.

## Requirements and costs

You provide the Claude, ChatGPT, or API-key accounts you choose to route. Claude
Max OAuth accounts may serve only Claude Code. API-key fallbacks bill per token,
and Jev requires an OpenRouter API key. Model Gateway stores credentials in BB's
plugin data directory and never returns secret values through its CLI or UI.
