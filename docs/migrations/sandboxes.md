# Sandboxes: public native runtime adapters

Sandboxes supplies native BB adapters for Daytona, Modal, E2B, Box, Freestyle and Nirvana. BB owns machine and environment lifecycle. Installing this package does not create a machine, build an image, import an existing installation or approve another plugin.

## Install one package

```sh
bb plugin install git:https://github.com/hemaaanth/oh-my-bb.git@main --plugin sandboxes
```

The package owns its dependencies, build, tests and documentation. No root installation or suite source switch is needed. Its managed-model runtime requires Model Gateway; there is no local-login fallback. Source installation, configuration and local status do not require optional siblings. A successful offline build does not certify provider accounts, network access or paid lifecycle operations.

For an existing installation, preserve plugin ID `sandboxes` and use BB's supported source change. Do not uninstall first. Keep the old source, dependencies and private recovery material until the canonical runtime, state and active-resource checks pass.

## Preserve live work before changing source

Capture separate restricted backups of code, the package database, native configuration and registration metadata. Verify a disposable restore and semantic comparison before applying schema or ownership changes. Preserve native provider/environment/host IDs, checkpoints, active jobs, image/default records, legacy selections, provider credentials, Browser holds and preview state. Do not log secret values or copy them into nonsecret preferences.

Check active provider, preparation, image and Browser operations before reload. A completed build, empty visible list or old timestamp does not prove idle. Do not stop, delete or recreate machines to make a source switch easier. Cancellation or a failed provider lookup is not proof that a resource was removed. Unknown cleanup retains its native resource and provider identity.

Activate only the reviewed published package through a single-plugin source change. Compare requested, resolved and runtime source roots, plugin/install identity and semantic state. Preserve unrelated checkout edits. Keep native launch and real UI acceptance separate from synthetic package tests.

## Settings and optional integrations

Static provider credentials remain in native Configuration under their existing key identities. Existing secret-file and absent-only dotenv readers remain supported. An explicit native value takes precedence. Verify effective identity privately; do not rotate or delete a working key during migration.

Nonsecret behavior moves once into revision-checked Preferences. Explicit destination false and empty values win. The first registration retains old native behavior fields for import; perform the documented Sandboxes-only finishing reload, then verify `migrationPending:false`. Hiding a declaration does not delete its stored value. After new preference edits, reverse-export them before restoring old code authority; never discard new work with an old database backup.

Credentials, Catalog, Agents and Projects call paths are off for fresh installs. An existing installation can import its inventoried effective behavior once with a generation/digest receipt. This preserves behavior; it does not manufacture past consent, approve skills or expand access. Named-flag changes preserve other clients' opt-outs. Browser owns its separate Sandboxes opt-in; there is no duplicate Browser gate.

Legacy attachment IDs remain a read-only projection at their original scope. No old selection is silently promoted to a global or project grant. Native lifecycle controls remain available. This release does not create another agent/project/sandbox pairing editor.

## Preparation status is not retry permission

Credentials owns preparation jobs. Sandboxes observes the exact native target and known job ID. Read-only status starts no work. Explicit same-job reconciliation does not replace a job.

A retry requires a fresh, strict `preparationOutcomeV1` response for that job with positive retry eligibility. Cached labels, legacy failure responses, missing jobs after reload or expiry, timeouts and transport uncertainty do not authorize replay. A lost start response remains unknown. Concurrent same-target retries share one operation.

Catalog participation remains unconfirmed under its older materialization contract, even when the old result says ready. Refresh cannot manufacture completion evidence. Local observation disposal does not cancel a remote process. This observation protocol is not a required-preparation-before-prompt barrier and does not invent source configuration revisions or remote cancellation.

## Preserve the image builder route explicitly

Fresh installs have no private builder default. Configure a supported builder and registry before image upgrades. For an existing installation, import its resolved route once through the supported owner action; retain the receipt. Runtime `BB_SANDBOX_IMAGE_BUILD_REPO` wins, then an explicit saved preference, then the imported route. An explicit empty preference disables the imported route.

The builder must support the three Browser source/input/archive inputs and emit matching immutable-image labels. This package does not supply a public workflow. A previously inferred private workflow is not assumed to exist in this public repository. Adapt and review that configured workflow before cutover; migration itself must not dispatch, build, register, activate or heal an image.

## Image provenance and rollback

The package-local Browser archive has a reviewed source/input/archive receipt. Verify it with `node docker/verify-browser-runtime.mjs`. Do not build from a live Browser root or substitute an old private sibling archive. Registration checks all three Browser labels against an immutable image reference.

An additive table stores image provenance; historical SQL identities remain unchanged. A separately reviewed compatibility list permits attested older artifacts without requiring equality with today's archive. Unknown or incompatible images cannot be newly activated or pinned. Existing image rows, defaults, native resources and sessions remain retained.

For an existing installation, recover and review immutable proof for needed legacy rollback targets before cutover. If proof cannot be recovered, an explicit owner decision must accept the precise temporary selection restriction. Do not hide that behavior change. A rebuild creates a new target; it does not preserve or prove an old rollback target. There is no arbitrary unknown-provenance override.

The unused broken standalone Freestyle snapshot publisher is not shipped. Native Freestyle runtime, configured snapshot selection, settings and stored snapshot data remain. No replacement bootstrap framework or cloud snapshot operation is part of this migration.

See [the package contract](../../plugins/sandboxes/CONTRACTS.md) for exact import inputs, precedence, retry semantics and recovery limits. Provider lifecycle, image building and network acceptance need separately bounded authorization; local fixtures are not substitutes for those checks.
